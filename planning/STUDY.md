## The pstack mental model in seven points

1. **Throughput without quality is not the goal.** "If you want to go fast,
   go deep first." Fewer, higher-quality changes; rigor is what makes
   parallelism safe ("fearless parallelism").
2. **Verification is the foundation.** A project-local verification skill
   (generated by `/create-verification-skill`, kept honest by
   `/maintain-verification-skill`) lets agents close the loop without the
   human as bottleneck. Part 1 claims most of the value lives here.
3. **Build the Lever.** For non-trivial work, the deliverable includes the
   tool that does or proves it (CLI, codemod, generator, delegate skill).
   Agent-friendly CLI properties: composable subcommands, `--dry-run` on
   destructive paths, descriptive errors that say what to do instead, rich
   `--help`, machine-readable output. "A deterministic lever beats fan-out."
4. **Feature Maps are materialized memory.** User-POV map (README index +
   one file per feature, four H2s) saves tokens and grounds verification.
   The map rots; maintenance is a scheduled routine, possibly oncalled.
5. **Parallelism via cloud agents, adjudicated.** Swarm fans out N cloud
   workers with standalone briefs and PASS/ISSUES/BLOCKED reports; arena
   bakes off alternatives and grafts. Dropouts are normal (proceed N-1).
6. **Models are roles, not identities.** Every delegation names an explicit
   model per role (fast mechanical vs judgment/prose), configured by
   `/setup-pstack` into an override rule, inline defaults otherwise.
   Multi-model panels exploit different strengths; cross-judges must differ
   in family from the author.
7. **poteto-mode is the router.** Sticky mode, todo-first, verbatim playbook
   steps, principles index with cited decisions, reply style (short
   declarative sentences, no em-dashes, consumer+maintainer framing).
   Gardener work (smell-watching, refactors, lints) is the payoff state.

## PI migration mapping (construct by construct)

- `/add-plugin pstack` -> `pi install <pstack-pi package>`.
- `subagent_type` agents (poteto-agent, Comment Sicko) -> no PI equivalent.
  poteto-agent becomes a documented working style inside poteto-mode;
  Comment Sicko becomes a read-only review checklist inside no-comments.
- Cloud workers -> sequential briefs + `git worktree` isolation via bash.
  Standalone briefs, report envelopes, and dropout tolerance survive intact.
- `~/.cursor/rules/pstack-models.mdc` -> `~/.pi/agent/pstack/models.md`
  (same line format), read by skills with inline-default fallback AND
  injected into the router text by the extension at session start.
- `disable-model-invocation: true` -> keep: PI's skills spec supports it.
- Sticky mode + per-turn reminder -> `before_agent_start` injection
  (built and transcript-proven).
- Todo discipline -> PI has no todo tool; extension registers a `pstack_todo`
  custom tool (stateful tools are an established PI pattern).
- Transcript access (`recall`, `reflect`, session-pickup, show-me-your-work,
  worktree-cleanup, `automate-me`) -> extension `pstack_transcripts` custom
  tool over PI session trees (same JSONL entry shape as OMP).
- Verification drivers (`control-cli`/`control-ui` from cursor-team-kit,
  CDP/browser) -> bash-driven harnesses: Playwright scripts, PTY helpers,
  curl, exit codes. Web poking via scriptable browsers only.
- `make-bot-ui` (Grok webhook + Tailscale) -> drop on PI.
- Benny automations -> drop (Cursor/Grok-specific).
- `/loop` + goal mode -> absent on PI; bounds via bash polling + caps.
- `deslop` (cursor-team-kit) -> drop; unslop covers prose.
- Upstream HEAD extras to carry: `disable-model-invocation` flags,
  forge-neutral playbook language, Fable-5.1-style defaults become
  "fast vs judgment" role language with PI model names at setup.
